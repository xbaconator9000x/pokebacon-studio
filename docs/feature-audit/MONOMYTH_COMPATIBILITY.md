# Pokémon Monomyth compatibility (v1.0, 32 MB, Emerald-based)

Measured on a real, legally acquired `monomyth_v1_0.gba`. No ROM data is in this repository. Re-run `node scripts/check-private-monomyth.mjs path/to/rom.gba` to repeat the map checks.

## Working (read and export of maps)
- Engine is detected as Ruby/Sapphire/Emerald data. Tilesets use three-layer (24-byte) metatiles with the attribute table stored after the metatile table. This is now detected (`metatileFormatAfterAttrs`).
- All 828 maps load. 661 have no tile problems. 166 have a few blocks whose tile numbers are past the end of the tileset's stored graphics (1.2% of their cells in total, six maps over 10%). The likely cause is tiles filled at runtime, for example animated tiles. This is not confirmed and these tiles render blank.
- Map 6.17's secondary tileset points at empty data and now loads with no graphics instead of failing.
- Exporting a map with no edits gives a byte-identical ROM (tested on 0.0).
- Exporting a repainted map writes new blocks after the original data, changes only layout pointers elsewhere, and the new ROM reads back with the edit.
- Exporting repoints every layout sharing that tileset pair to the new tilesets. One other sharing map (0.12) was pixel-identical afterwards.

## Not working or not checked
- **Dialogue (read-only).** Packed `FC 1D` dialogue now decodes to readable English (6-bit packed stream with a 245-word dictionary, worked out from the game's own text routine). In the first 80 maps, 2,169 of 2,351 story texts are packed and decode; one text with control code `FC 1A` is still unreadable. Packed text can be edited: edits are re-packed, spelled out letter by letter rather than with the word dictionary, so edited text takes more room (it is relocated, so this is safe). In the first 120 maps, every packed text that can be re-packed decodes back to itself exactly; a small number containing accented or Japanese characters are rejected cleanly. `FC 19 xx` / `FC 1C xx` codes appear as `\xfc\x19\xNN` tokens; their meaning is not yet confirmed.
- **Species and moves (new).** Monomyth keeps 405 species (24-byte records, 11-byte names) and 680 moves (16-byte records) in tables with no header pointers. They are found by structure. Editable and verified on the real ROM: species name, six stats, two types, catch rate, gender ratio, egg cycles, friendship; move name, effect, power, type, accuracy, PP, secondary chance. Not yet decoded, so shown hidden and refused if changed: abilities, base experience, EV yield, held items, growth rate, egg groups, level-up moves, evolutions. Items: 447 records of 32 bytes (name, price at +30); name and price are editable, hold effects are not decoded and refuse changes. Trainers: 640 records of 40 bytes at 0x4b6c84 with 116 trainer classes. The party layout was read from the game's own party-loading routine: members are 12, 16, 20 or 24 bytes depending on the flags byte (1 = custom moves, 2 = held item). Each member has a personality value, IV quality, level, species, optional held item, optional four moves and two trailing bytes that are not decoded (kept as they are on edit). All 2,080 party members in the ROM pass range checks. Trainer name, class, bag items, double-battle flag and teams are editable; an edited team is moved to new space and the trainer's pointer updated.
- **Story scripts.** Across all 828 maps the story indexer reads 9,276 event roots and about 90,000 commands; 228 commands (0.25%) are unreadable and stay untouched. Plain and packed dialogue edits both export and read back on the real ROM.
- Event structures (NPCs, warps, signs, triggers) have standard sizes and parse sensibly (8,396 of 8,428 NPCs kept; null scripts and the dynamic warp 127.127 are normal). Script commands decode for the first 80 maps, apart from the text above. Nothing has been checked against the game's own custom routines.
- Running an exported ROM in an emulator or on a device has not been done. Exported ROMs are unverified in play.
- Editing events, scripts, trainers and species on Monomyth is not enabled or reviewed. No Monomyth engine profile exists yet.
