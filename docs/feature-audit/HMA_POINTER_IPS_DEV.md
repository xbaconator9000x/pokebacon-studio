# HMA pointer navigation, copy-on-write repointing and IPS — development evidence

Updated 12 November 2026 · PR #29 · `development/studio-upgrades`.

## Implemented in the real editor

**Pointer follow and "where-used".** `dist/hma-pointer-navigation.js` reads source-matched staged bytes as genuine little-endian `0x08/0x09` GBA ROM pointers, including raw/untyped candidate sites, typed `ptr` fields and HMA `[[OffsetPointer]]` metadata that carries a bias. The mobile ROM hex workspace has a dedicated **Pointers** tab for entering a source offset or target offset, navigating to the pointed-to asset, listing users, inspecting source addresses, and returning to the hex view. Imported HMA named anchors offer a direct **References** button; pointer cells in typed tables open the same inspector.

Reference search is explicitly **not automatic proof of ownership**. An arbitrary sequence matching a pointer can be incidental data; executable ROM code can synthesize pointers at runtime. In repoint preflight, a full source byte-pattern scan including unaligned/packed direct pointers and explicitly documented HMA offset sources is intentionally conservative. The scan is capped at 65 matches when checking repoint completeness; any unseen, additional or offset pointer source fails closed. Unrecognized dynamic calculations remain outside certification.

**Guarded native table copy and repoint.** A manually described, source-bound table now has **Review table repoint**. The editor displays every discovered direct user and asks which pointer sites are approved. A persisted, undoable `repoints` plan references the original table ID, address and exact byte length. `installSafeTableRepoints` rejects changed schemas, duplicate ownership, missing/unreviewed/offset users, new conflicting native writer modifications at any pointer site, and malformed original ROM pointers. Upon export, the authoritative `RomOutput` copies the **final edited native table bytes** to newly allocated ROM space, then rewrites all approved direct pointer sites through its standard write tracker. Original table bytes are retained rather than wiped. The exact allocation address is determined during the real export; reimport and GBA-reader tests verify the result.

This is **same-size copy-on-write relocation**, not generalized HMA linked-table expansion. Row counts remain unchanged; no engine counter, hardcoded table length, special compression, active battle routine, bytecode pointer semantics or custom ROM hack behavior is inferred. A source-only export includes queued repoints, as does the full project ROM writer. Preview and project save/reopen retain the plan.

**Verified fixed numeric HMA formats.** An HMA named anchor using the strict grammar `[field. field: field::]COUNT` can be imported as a typed little-endian table; `.` is 8-bit, `:` 16-bit, and `::` 32-bit. HMA dynamic table counts, named symbolic lengths, script pointers, enums, bitfields, Gen III encoded text, image/compressed formats, or complex `Format` expressions remain **read-only source metadata**, preserved verbatim and never guessed. A manually defined numeric table remains the fallback.

**IPS patch creation and application.** `dist/ips.js` implements the established **PATCH / records / EOF** binary format, including non-RLE encoding of modified runs, RLE decoding, optional 24-bit truncation and safe handling of data at the reserved `0x454F46` EOF marker. Generated IPS patches are applied internally and compared byte-for-byte against the edited result before being offered to the user. Both **Save compiled ROM → Create IPS patch** and **hex workspace → Create source-only IPS patch** are available. **Apply patch** now accepts `.ips` beside BPS and UPS. Standard IPS cannot represent arbitrary changes at 16 MiB+ offsets, so these operations fail with a BPS recommendation; they never silently truncate expanded ROM content. IPS has **no source checksum**: users must retain and select the correct original ROM, unlike BPS/UPS.

## Tests, evidence and limits

- `tests/hma-pointer-repoint.test.js`: original synthetic GBA ROM native pointers, HMA biased pointers, aligned+unaligned packed direct source references, unknown/duplicate users rejected, table schema and compiler collision abort before writes, staged table-byte migration, reindexed native GBA maps, identical original ROM bytes and preserved repoints through split project save/reopen and undo/redo.
- `tests/ips.test.js`: genuine synthetic GBA ROM title edit roundtrip plus map reindex, >65,535-byte changes split into records, reserved EOF address, RLE decode, target size change, malformed input refusal and >16 MiB changed offset rejection.
- `tests/hma-pointer-repoint.test.js`: safe HMA `[. : ::]` numeric subset versus unsupported complex syntax. The raw HMA TOML text is retained without loss.
- `scripts/test-release-mobile-browser.mjs`: physical phone-sized Chromium exercises native hex, typed fields, source pointer "where-used" and follow, anchor-derived numeric table import, approved repoint queue, then IndexedDB save/reload.
- The prior `HMA_HEX_TABLE_FOUNDATION_DEV.md` and `HMA_PARITY.md` remain authoritative. **HMA parity items stay not-verified end-to-end** pending real Pokémon engine/runtime tests and user Android device acceptance. No signed APK is generated, and no user-specific Shattered file has been executed in this batch.
